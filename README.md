# STOQ

React, TypeScript, Vite, Mantine, Redux Toolkit и React Router.

Запуск: `npm install`, затем `npm run dev`.

Первая страница дашборда подключена к заказам, каталогу и WebSocket склада: графики выручки, расчётной прибыли и заказов за 7/14/30 дней, средний чек, низкие остатки и сроки годности. Формулы и ограничения расчёта: [docs/dashboard.md](docs/dashboard.md).

Поставки поддерживают выбор статуса при создании и редактирование на `/supply/:id/edit`. «Принять поставку» открывает форму ожидаемой поставки со статусом «Принята»; склад пополняется после сохранения. Использованные партии защищены от изменения состава. Списание доступно в таблице и на странице складской партии, с подтверждением и записью движения. Рекомендованные блюда гостевого меню отмечены «Советуем».

На `/test` доступны связанное наполнение каталога и склада, внешняя демопоставка «В пути» и подтверждаемый сброс рабочих данных. Наполнение вызывает `/product/few` и `/dishes/batch` и использует возвращённые ID. Сброс сохраняет аккаунты и единицы измерения; в production backend требует `ENABLE_TEST_TOOLS=true` на gateway, inventory, catalog и order. Проверки сценариев: `node --experimental-strip-types --test scripts/test-panel.test.mjs scripts/supply-api.test.mjs scripts/store-api.test.mjs`.

Демо-набор содержит обычные названия без служебных суффиксов, фотографии блюд из Яндекс Картинок ([омлет](https://yandex.ru/images/search?text=омлет%20с%20томатами), [капрезе](https://yandex.ru/images/search?text=капрезе), [блины](https://yandex.ru/images/search?text=блины)) и 8 партий: основные запасы на 3–365 дней и дополнительные партии молока на 2 минуты и моцареллы на 5 минут от запуска заполнения. Фото загружаются по внешним HTTPS-ссылкам. Повторное заполнение использует существующие продукты и блюда с теми же названиями, добавляя новые складские партии.

Отдельная кнопка «Добавить поставку с маленьким сроком жизни» создаёт принятую поставку из двух существующих продуктов (предпочтительно молоко и моцарелла) со сроками через 1 и 2 минуты. Если в каталоге один продукт, создаётся одна партия на 1 минуту; пустой каталог нужно сначала заполнить.

Деплой frontend на VPS Selectel, CI/CD, домен на Beget и инструкция по SSH-туннелю к локальному бэкенду: [deploy/README.md](deploy/README.md). Автодеплой запускается при push в `main`; тесты в CI не выполняются.

Перед `npm run build` автоматически проверяются локальные импорты и регистр путей в Git (`npm run check:imports`). Это ловит несовпадения, которые Windows допускает, а Linux на Vercel отклоняет. Для Vercel используйте Build Command `npm run build`. При переименовании папок только по регистру фиксируйте изменение через промежуточное имя (`git mv old temporary`, затем `git mv temporary New`). Отключение `tsc` не отменяет необходимость разрешать импорты в Vite.

Вкладки «Стоп-лист» и «Горячие предложения» получают данные через Socket.IO namespace `/recommendations`. Адрес задаётся в `VITE_WEBSOCKET_API_URL` (например, `ws://26.130.106.197:3000`); без него используется `VITE_API_URL`. Стоп-лист отправляет `recommendations:getStopList` с `{ requestId: "stopListId", search }`, рекомендации — `recommendations:getDishRecommendations` с `{ requestId: "recommendedListId" }`. Ответы `{ requestId, data }` приходят в `recommendations:stopListResult` и `recommendations:dishRecommendationsResult`. Событие `recommendations:stopListUpdated` обновляет активную вкладку с сохранением поиска. При уходе с вкладки соединение закрывается; ошибки отображаются с кнопкой повтора. Проверка: `node --experimental-strip-types --test scripts/recommendation-socket.test.mjs scripts/desktop-protocol.test.mjs`.

При создании поставки кнопка «Отсканировать УПД» открывает загрузку PNG, JPEG, WEBP или PDF до 20 МБ. Файл отправляется в `POST /ai/supply` gateway: распознавание подготавливает товары каталога, пропускает доставку и возвращает их идентификаторы. Поставщик, количество, единицы и суммы добавляются в форму; существующие строки сохраняются. Номер поставки и сроки годности нужно заполнить вручную. Сумма строки берётся из `totalPrice`, без пересчёта по распознанной цене за единицу.

Для этого сценария backend должен содержать обновлённые gateway и catalog-service. `POST /ai` сохраняет прежний контракт распознавания.

Сохранённые заказы показывают серверные `totalPrice` и снимки цен позиций. До отправки формы сумма остаётся предварительным расчётом. Для старых неизвестных цен отображается «—»; выручка дня также неизвестна, если у завершённого заказа нет суммы.

Гостевое меню исключает блюда без доступных порций, без заданной цены и архивные/остановленные блюда. Доступность проверяется также при добавлении из страницы блюда и корзины.

В гостевом меню первые 10 доступных блюд из Socket.IO-рекомендаций показываются перед остальным каталогом без дублей. На странице до 12 блюд; поиск возвращает на первую страницу. Если рекомендации недоступны, остаётся обычное меню. Корзина создаёт заказ через существующий `POST /orders` с ISO-датой, типом, столом, количеством гостей и позициями `{ dishId, quantity }`. Цены рассчитывает сервер. После успешного ответа корзина очищается, а подтверждение открывается с `orderId` в URL и восстанавливается через `GET /orders/:id` после перезагрузки. Ошибка сохраняет корзину для повтора. Создание заказа не выполняет оплату. Текущий API заказов не принимает `restaurantId`, имя гостя и комментарий. Браузерная проверка: `node scripts/guest-checkout-ui.smoke.cjs <каталог-с-Playwright>`; адрес Vite задаётся через `GUEST_UI_URL`.

Проверки frontend: `npm run typecheck`, `npm test`, `npm run build`. Браузерный тест адаптива: `node scripts/responsive-smoke.cjs <каталог-с-Playwright>` при запущенном Vite на 5173. Он использует тестовые API-ответы, обходит текущие страницы на ширинах 320–1440 px и проверяет заполненные формы, гостевую корзину, модалки и короткие экраны.

Граф зависимостей открывается отдельной вкладкой «Граф связей» в tab bar страницы «Блюда» и напрямую загружается из `GET /analytics/graph` через gateway. Recommendation-service рассчитывает узлы, связи и статусы, которые frontend отображает без пересчёта. Режим «По блюду» показывает только выбранное блюдо и его ингредиенты в двух колонках; боковая панель содержит поиск, фильтр проблемных блюд и состав с количеством «Нужно / Есть». По умолчанию выбирается первое проблемное блюдо, если оно есть. «Вся карта» возвращает полный граф; клик по блюду открывает его состав. Доступны загрузка, пустое состояние, ошибка с повтором и кнопка обновления. Изменения склада, поставок, продуктов и блюд обновляют кеш графа по существующим тегам API. Проверка графа в браузере: `node scripts/dish-dependency-graph-ui.smoke.cjs <каталог-с-Playwright>`; для другого адреса Vite можно задать `DISH_GRAPH_UI_URL`.
## Локальная разработка с удалённым HTTP-бэкендом

В `.env` укажите `API_PROXY_TARGET=http://<адрес-компьютера>:3000` и запустите
`npm run dev`. Текущий адрес бэкенда уже перенесён в эту настройку.
После изменения `.env` или настройки прокси перезапустите Vite и войдите заново.

В режиме разработки браузер отправляет HTTP-запросы на `/api` своего фронта,
а Socket.IO — на `/socket.io` того же адреса. Vite пересылает оба вида запросов
на gateway. Это также работает при `npm run desktop:dev`.

Локальный прокси сохраняет `HttpOnly` и срок жизни auth-cookies, убирает привязку
к домену удалённого сервера и устанавливает `SameSite=Lax`. При HTTP-соединении
с фронтом снимается `Secure`, а refresh-cookie получает путь `/api/auth`.
Таким образом, cookies сохраняются браузером, refresh и выход используют тот же
адрес, а access-cookie доступна для WebSocket. Настройки cookies и код бэкенда
для этого менять не требуется.

Эта настройка действует для dev-сервера Vite. Production-сборки и упакованное
desktop-приложение продолжают использовать `VITE_API_URL` и
`VITE_WEBSOCKET_API_URL`; для них нужен отдельный прокси или HTTPS.
Прокси устраняет ограничения браузера, но не шифрует HTTP-трафик до бэкенда.

Проверки прокси: `node --experimental-strip-types --test scripts/dev-api-proxy.test.mjs`.
Браузерная проверка на локальном тестовом сервере:
`node --experimental-strip-types scripts/dev-cookie-proxy.smoke.mjs <каталог-с-Playwright>`.
