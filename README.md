# STOQ

React, TypeScript, Vite, Mantine, Redux Toolkit и React Router.

Запуск: `npm install`, затем `npm run dev`.

Вкладки «Стоп-лист» и «Горячие предложения» получают данные через Socket.IO namespace `/recommendations`. Адрес задаётся в `VITE_WEBSOCKET_API_URL` (например, `ws://26.130.106.197:3000`); без него используется `VITE_API_URL`. Стоп-лист отправляет `recommendations:getStopList` с `{ requestId: "stopListId", search }`, рекомендации — `recommendations:getDishRecommendations` с `{ requestId: "recommendedListId" }`. Ответы `{ requestId, data }` приходят в `recommendations:stopListResult` и `recommendations:dishRecommendationsResult`. Событие `recommendations:stopListUpdated` обновляет активную вкладку с сохранением поиска. При уходе с вкладки соединение закрывается; ошибки отображаются с кнопкой повтора. Проверка: `node --experimental-strip-types --test scripts/recommendation-socket.test.mjs scripts/desktop-protocol.test.mjs`.

При создании поставки кнопка «Отсканировать УПД» открывает загрузку PNG, JPEG, WEBP или PDF до 20 МБ. Файл отправляется в `POST /ai/supply` gateway: распознавание подготавливает товары каталога, пропускает доставку и возвращает их идентификаторы. Поставщик, количество, единицы и суммы добавляются в форму; существующие строки сохраняются. Номер поставки и сроки годности нужно заполнить вручную. Сумма строки берётся из `totalPrice`, без пересчёта по распознанной цене за единицу.

Для этого сценария backend должен содержать обновлённые gateway и catalog-service. `POST /ai` сохраняет прежний контракт распознавания.

Сохранённые заказы показывают серверные `totalPrice` и снимки цен позиций. До отправки формы сумма остаётся предварительным расчётом. Для старых неизвестных цен отображается «—»; выручка дня также неизвестна, если у завершённого заказа нет суммы.

Гостевое меню исключает блюда без доступных порций, без заданной цены и архивные/остановленные блюда. Доступность проверяется также при добавлении из страницы блюда и корзины.

В гостевом меню первые 10 доступных блюд из Socket.IO-рекомендаций показываются перед остальным каталогом без дублей. На странице до 12 блюд; поиск возвращает на первую страницу. Если рекомендации недоступны, остаётся обычное меню. Корзина создаёт заказ через существующий `POST /orders` с ISO-датой, типом, столом, количеством гостей и позициями `{ dishId, quantity }`. Цены рассчитывает сервер. После успешного ответа корзина очищается, а подтверждение открывается с `orderId` в URL и восстанавливается через `GET /orders/:id` после перезагрузки. Ошибка сохраняет корзину для повтора. Создание заказа не выполняет оплату. Текущий API заказов не принимает `restaurantId`, имя гостя и комментарий. Браузерная проверка: `node scripts/guest-checkout-ui.smoke.cjs <каталог-с-Playwright>`; адрес Vite задаётся через `GUEST_UI_URL`.

Проверки frontend: `npm run typecheck`, `npm test`, `npm run build`. Браузерный тест адаптива: `node scripts/responsive-smoke.cjs <каталог-с-Playwright>` при запущенном Vite на 5173. Он использует тестовые API-ответы, обходит текущие страницы на ширинах 320–1440 px и проверяет заполненные формы, гостевую корзину, модалки и короткие экраны.

Граф зависимостей открывается отдельной вкладкой «Граф связей» в tab bar страницы «Блюда» и напрямую загружается из `GET /analytics/graph` через gateway. Recommendation-service рассчитывает узлы, связи и статусы, которые frontend отображает без пересчёта. Режим «По блюду» показывает только выбранное блюдо и его ингредиенты в двух колонках; боковая панель содержит поиск, фильтр проблемных блюд и состав с количеством «Нужно / Есть». По умолчанию выбирается первое проблемное блюдо, если оно есть. «Вся карта» возвращает полный граф; клик по блюду открывает его состав. Доступны загрузка, пустое состояние, ошибка с повтором и кнопка обновления. Изменения склада, поставок, продуктов и блюд обновляют кеш графа по существующим тегам API. Проверка графа в браузере: `node scripts/dish-dependency-graph-ui.smoke.cjs <каталог-с-Playwright>`; для другого адреса Vite можно задать `DISH_GRAPH_UI_URL`.
